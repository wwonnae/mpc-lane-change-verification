## 7. Student 입력 정정과 폐루프 검증

### (1) 제출본 입력 명세의 결함 — 계산으로 확인

제출본 MPC는 상태 x = [y, ψ]를 초기값으로 받아 최적 조향을 푼다(식 4~6). 그런데 Student 입력 9차원에는 헤딩 ψ가 없다.

- **반례**: Student 입력(속도, ey, front_gap, left_clear, 상태)을 고정하고 초기 헤딩 ψ0만 −30°, −15°, 0°, +15°, +30°로 바꾸면, 제출본 설계의 MPC
  (baseline v1.1)가 내는 첫 조향은 {{n:obs_psi_demo}}이다. 같은 입력에 서로 다른 정답이 대응하므로, 어떤 함수도 9차원 입력만으로 이 MPC를
  모방할 수 없다. 모델 크기나 데이터 양의 문제가 아니다.
- **데이터 확인**: 개발 데이터에서 Student 입력을 센서 분해능 수준의 격자로 묶으면, 같은 칸 안의 조향 분산이 전체 분산에서 차지하는 비율이
  표 6-7a와 같다. ψ를 더하면 이 몫이 거의 사라지고, 같은 칸 크기의 **섞은(위약) ψ**를 더하면 그대로 남는다 — 줄어든 것은 칸을
  잘게 나눈 효과가 아니라 ψ가 가진 정보 때문이다.

**표 6-7a. 입력 격자 안에서 설명되지 않는 교사 조향 분산.** [데이터: D | 호스트: H1 | 버전: 교사 baseline v1.1 · v2 MPC | 커밋: C5]

| 입력 | 교사 = 제출본 설계 MPC(baseline) | 교사 = improved v2 |
|---|---|---|
| 9차원(제출본) | {{n:obs_baseline_9}} | {{n:obs_v2_9}} |
| 9차원 + 섞은 ψ(위약) | {{n:obs_baseline_psipl}} | {{n:obs_v2_psipl}} |
| 9차원 + ψ | {{n:obs_baseline_psi}} | {{n:obs_v2_psi}} |
| 9차원 + ψ + δ_prev | {{n:obs_baseline_psidp}} | {{n:obs_v2_psidp}} |

{{fig:F6}}

**분류.** ψ 추가는 [개정]이다 — 제출본 자신의 MPC를 제출본 입력 명세로는 모방할 수 없음이 계산으로 증명되었고, 이는 초기 위치 절단·복귀
임계값과 같은 기준("계산·분석으로 불가능이 증명된 명세만 수정")이다. 직전 조향 δ_prev는 제출본 MPC의 비용함수에 항이 없어 제출본 설계에는
필요 없고, 교사 v2의 변화율 제약(I1)에서만 영향을 준다(δ_prev를 −20°~+20°로 바꾸면 v2의 첫 조향이 {{n:obs_dprev_demo}}). 그래서 δ_prev
추가는 [발전]으로 두었다.

### (2) S10·S11 학습과 개발 데이터에서의 선택

입력만 다르고 데이터·분할·구조·설정은 모두 같게 두고 두 모델을 학습하였다: S10(9차원 + ψ, [개정]만), S11(S10 + δ_prev). 선택 epoch와
검증 손실은 S10 {{n:S10_best}}, S11 {{n:S11_best}}였다(9입력은 {{n:i4_best}}).

**표 6-7b. 개발 데이터 비교.** [데이터: D | 호스트: H1 | 버전: Student 9입력 · S10 · S11 | 커밋: C5]

| 모델 | 개루프 MAE(검증 분할) | 폐루프 paper 성공/충돌/타임아웃 | 폐루프 S3 성공/충돌/타임아웃 |
|---|---|---|---|
| 9입력 | {{n:dev_9_mae}} | {{n:dev_9_dev_paper}} | {{n:dev_9_dev_s3}} |

선택 규칙은 실행 전에 정하였다: S11이 폐루프 성공·충돌에서 S10보다 유의하게 나을 때만(McNemar 정확검정 p < 0.05) S11, 그 밖에는 입력이
적은 S10. 두 모델의 폐루프 결과가 에피소드마다 같아 **S10**을 골랐다. 개루프 MAE는 S11이 낮지만 선택에 쓰지 않는다고 미리 정하였다.
S10은 9입력보다 개발 데이터에서 성공한 쌍이 압도적으로 많았다(S10만 성공 / 9입력만 성공 = {{n:dev_mcnemar_S10_9}}).

### (3) 최종 확인 — E3 (한 번만 실행)

개발 데이터는 학습 시나리오와 같은 집합이어서 낙관적일 수 있다. 한 번도 쓰지 않은 E3(부록 B)로 한 번만 확인하였다. 판정 기준도 실행 전에
정하였다 — 통과: v2 MPC 대비 충돌이 많지 않고 성공이 적지 않음(paper·S3 각각), 부분 개선: 통과는 못 했지만 9입력 대비 유의하게 나음, 그 밖은 실패.
