## 6. 개선: I1·I1b·I2'·I3·I5

VI장 2절과 5절에서 확인된 baseline의 한계(장애물을 모르는 비용함수, 변화율 제한을 모르는 재계획, 풀이 실패 시 약한 fallback)를 제출본에
없는 개선으로 다뤘다. baseline 코드는 이 단계 동안 동결했고, 개선은 별도 코드(`thesis_v2/improved/`)에서 항목마다 켜고 끌 수 있게
만들었다. 파라미터는 해석적으로 정하거나 개발 데이터 D에서만 정했으며, 평가 데이터로는 아무것도 조정하지 않았다.

### (1) 개선 항목

**표 6-6. 개선 항목과 파라미터 근거.** [데이터: 설정값 | 호스트: 해당 없음 | 버전: improved v1 · v2 | 커밋: C2]

| 항목 | 무엇을 바꾸나 | 파라미터 | 근거 |
|---|---|---|---|
| I1 변화율 인지 | MPC가 직전 조향을 입력받아 첫 입력에 변화율 하드 제약을 둠 | {{n:rate_step}} | 후처리 제한과 같은 값 — MPC가 실제로 낼 수 없는 조향을 계획하지 않도록 |
| I1b 소프트 위치 제약 | 위치·헤딩 제약을 슬랙 변수와 ℓ1 벌점으로 완화(풀이 불가 대신 최소 위반) | ρ = {{n:rho_i1b}} | 원 제약 문제의 라그랑주 승수 상한을 해석적으로 추정하고 안전계수를 둔 exact penalty 값 |
| I2' 장애물 인지 | front_gap이 가까울 때 y에 장애물 회피 하한을 두고, 그동안 헤딩 하한(−20°)을 함께 둠 | 마진 {{n:margin_i2p}} | 헤딩을 20° 이내로 묶었을 때 회전한 차체 모서리의 최악 오프셋(해석 도출) |
| I3 warm-start fallback | 풀이 실패 시 비례 제어 대신 직전 해를 한 스텝 밀어 사용 | — | 직전 해는 실행 가능했던 계획이므로 비례 제어보다 교정력이 클 것으로 보고 채택(설계 근거) |
| I5 반복 상한 | OSQP 반복 수에 상한을 두고 상한에서 나온 근사해가 하드 제약을 어기면 폐기 | {{n:i5_cap}} | 시간 예산 후보({{n:i5_budget}}) 중 개발 데이터에서 안전성 비열화가 없는 가장 낮은 값 |

v1 = I1 + I1b + I2' + I3, v2 = v1 + I5이다. 각 항목을 단독·조합으로 개발 데이터에서 비교한 뒤(ablation, `thesis_v2/results/dev_ablation/`) 조합을 확정하였다. 평가 데이터에서는
baseline·v1·v2 세 조합만 비교했으며(그림 F5), 항목별 단독 효과는 평가 데이터에서 분리하지 않았다.

### (2) 안전성 결과

- **E1(개선 v1 첫 평가)**: paper 충돌 {{n:e1_paper_base}} → {{n:e1_paper_v1}}(차이는 유의하지 않음, 쌍대 정확검정 {{n:e1_paper_mcn}}), S3 격자 실패 {{n:e1_s3_base}} → {{n:e1_s3_v1}}.
- **E2(v2 포함 3자 비교)**: 모든 시나리오에서 v1·v2의 충돌이 0이었고(표 6-5), paper 성공은 v2 {{n:e2_paper_v2_success}}이다. 두 개선판 사이에
  성공이 실패로 뒤집힌 에피소드는 없었다.

**제약 만족(핵심 전제 1).** I1b는 위치·헤딩 제약을 소프트화하므로, 개선판에서는 "MPC 원출력이 원래의 하드 제약을 지키는가"를 따로 센다.

v2에서는 반복 상한에서 멈춘 근사해 가운데 하드 제약을 어기는 것은 쓰지 않고 fallback으로 넘겼으며(표의 폐기 수), 차량에 들어간 조향 중

- 소프트 제약(I1b)을 넣은 v1은 풀기 어려운 구간에서 반복이 솔버 상한까지 늘어 꼬리 계산 시간이 커졌다. 특히 left_obstacle에서 좌우가
  모두 막혀 SAFE_STOP 직전인 스텝들이 반복 상한(20,000회)에 도달하였다. 이 스텝들은 수렴 판정 전에 반복 한도에서 멈춘 것으로, 근사해는
  하드 제약을 통과했고 fallback은 0건이었다(발산이 아님).
- v2는 반복을 {{n:i5_cap}}회에서 끊어 모든 시나리오의 p99를 1 ms대로 낮췄다. v2의 p99는 공식 조건 네 번의 실행에서
  {{n:v2_p99_range}}로 안정적이었다(반복 횟수 분포가 실행마다 같음 — 계산량이 결정론적).
- baseline의 p99가 가장 작은 것은 소프트 제약·장애물 하한이 없는 작은 QP이기 때문으로 보인다. 개선판은 계산 시간을 더 쓰는 대신 E2 전 조건에서
  충돌이 관측되지 않았다(합산 {{n:e2_coll_pool_base}} → {{n:e2_coll_pool_v2}}, {{n:e2_coll_pool_p}}). 시나리오별로는 paper만으로는
  유의하지 않다(성공 쌍대 정확검정 {{n:e2_paper_mcn}}).
