# IV. 의사결정 및 경로 계획

## 1. 유한상태기계 기반 의사결정

FSM은 제출본과 같은 5개 상태(KEEP_L2, EVADE_L, KEEP_L1, RETURN_TO_L2, SAFE_STOP)를 쓴다. 상태 전이 조건은 표 2와 같고, 한 곳만
제출본과 다르다.

**표 2. 상태 전이 조건(제출본 대비).** [데이터: 설정값 | 호스트: 해당 없음 | 버전: baseline v1.1 | 커밋: C2]

| 현재 → 다음 | 제출본 조건 | 이 보고서의 조건 | 태그 |
|---|---|---|---|
| KEEP_L2 → EVADE_L | {{s:24}} | {{c:24}} | [정합] |
| 모든 상태 → SAFE_STOP | {{s:25}} | {{c:25}} | [정합] |
| EVADE_L → KEEP_L1 | {{s:20}} | {{c:20}} | [정합] |
| KEEP_L1 → RETURN_TO_L2 | t > {{s:21}} | t > {{c:21}} 그리고 right_clear | [해석] |
| RETURN_TO_L2 → KEEP_L2 | \|y\| ≤ {{s:22}}, \|ψ\| {{s:23}} | \|y\| ≤ {{c:22}}, \|ψ\| {{c:23}} | **[개정]** |

**[개정] RETURN_TO_L2 → KEEP_L2의 위치 임계값.** 제출본의 두 확정값이 서로 호환되지 않음이 실행 전 계산으로 확인되었다. 복귀
완료 조건은 |y| ≤ 0.20 m인데, 전이 직후 적용되는 KEEP_L2 위치 제약은 |y| ≤ 0.15 m이다(IV장 2절). 임계값 가까이에서 전이하면 한
스텝 안에 {{n:rev1_need}}를 움직여야 하지만, 한 스텝의 최대 이동량은 {{n:rev1_step}}이다. 따라서 0.15 < |y| ≤ 0.20 m에서 전이하고
곧바로 MPC가 호출되면 그 스텝의 QP는 구조적으로 풀 수 없고(infeasible), 그 스텝의 조향은 "MPC가 계산한 제약 만족 조향각"이 아니게 된다. EVADE_L →
KEEP_L1 조건과 대칭이 되도록 임계값을 {{c:22}}로 바꿨고, 헤딩 조건은 이 충돌과 무관해 그대로 두었다.

제출본에 없는 동작은 다음과 같이 최소 가정으로 채웠다.

- **SAFE_STOP은 종단 상태**이다(복귀 조건이 서술되지 않음). 이 상태에서는 속도 0, 조향은 직전 값을 유지한다.
- **상태 전이 쿨다운**({{c:14}})은 에피소드 시작 시 이미 만료된 것으로 둔다(첫 전이를 인위적으로 늦추지 않도록).
- **KEEP_L1 → RETURN_TO_L2**에는 최소 유지 시간과 함께 오른쪽 차선이 비었는지(right_clear)를 요구한다. 제출본 본문의 "장애물을 완전히
  통과할 때까지 1차선을 유지한다"를 조건으로 옮긴 것이다([해석], `SETTINGS_DECISION.md` §14).

조향 변화율 제한은 {{c:26}}이며, 뒤의 후처리 단계에서 적용한다(본 장 4절).

## 2. MPC 기반 횡방향 경로 계획

### (1) 모델과 비용함수

MPC는 제출본 식 (4)~(5)의 2-상태(y, ψ) 선형 모델과 식 (6)의 비용함수를 그대로 쓴다. 가중치와 예측 구간은 표 3과 같으며 모두
고정 파라미터이다.

**표 3. MPC 비용함수 가중치(제출본과 동일).** [데이터: 설정값 | 호스트: 해당 없음 | 버전: baseline v1.1 | 커밋: C2]

| 파라미터 | 값 | 의미 |
|---|---|---|
| q_y | {{c:28}} | 횡방향 오차 |
| q_ψ | {{c:29}} | 헤딩 |
| r_δ | {{c:30}} | 첫 조향 입력의 크기 |
| r_Δδ | {{c:31}} | 연속 조향 입력의 차분 |
| N | {{c:32}} | 예측 구간({{c:27}} 간격) |

식 (6)의 두 입력 항은 대상이 다르다. r_δ는 첫 입력 δ₀의 크기에만, r_Δδ는 연속한 입력의 **차분** (δᵢ − δᵢ₋₁)에 곱해진다. 차분 항은
대각 행렬만으로는 표현되지 않으므로, 이 보고서의 MPC는 이를 비대각 항을 가진 Hessian으로 구현하였다.

**제출본 결과를 만든 코드와의 차이(재현 과정에서 확인된 사실).** 제출본의 수치를 만든 것으로 보이는 옛 MPC 코드(`legacy_2025/final_hierarchical_backup_thesis_1204.py`)를 같은
입력으로 비교한 결과, 식 (6)과 다르게 동작하는 부분이 두 곳 확인되었다.

1. Hessian 대각에는 가중치 원값을, 선형항에는 2배 계수를 넣어, 무제약 최적점이 목표선이 아니라 목표선의 두 배 위치가 된다. 목표선이
   0.30 m인 상태(EVADE_L·KEEP_L1)에서 차량이 정확히 목표선 위에 있어도 +25°(최대 조향)를 낸다.
2. r_Δδ 항이 차분이 아니라 크기 벌점으로 구현되어 있다.

이 보고서의 MPC는 식 (6)을 표준 QP 형태로 새로 구현해 두 차이가 없다. 옛 코드와의 조향 차이는 격자 비교에서 이 두 차이와 상태별
위치 제약 차이로 대부분 설명되었다(`repro/docs/SPEC_VS_OLDCODE.md`). 다만 target_y = 0 근방의 잔여 격자는 옛 코드의 r_Δδ를 차분형으로
바꿔도 {{n:ctrack_resid}} 남아, 차이를 완전히 분리하지는 못하였다(`repro/docs/THESIS_REVISION_LOG.md` 2026-09-23 추가 검증). 제출본 VI장의 Student 오차(표 15)가 어느 구현을 교사로 삼았는지는
확인하지 못하였다(부록 A).

### (2) 제약조건

조향각 {{c:33}}, 헤딩각 {{c:37}}, 횡방향 위치는 상태별로 L2 주행 {{c:34}}, L1 주행 {{c:35}}, 차선 변경 구간 {{c:36}}이다(제출본과 동일).

### (3) 풀이와 fallback

QP는 OSQP로 풀고 warm-start를 쓴다. 제출본은 솔버 설정(수렴 허용오차, 반복 상한, polishing, 예외 처리)을 서술하지 않아, 라이브러리
버전이 바뀌어도 동작이 같도록 이 설정들(허용오차·반복 상한·polishing·warm-start·예외 처리)을 코드에 고정하였다(`SETTINGS_DECISION.md` §18). "제약 만족" 판정의 허용오차는 이 솔버의
실제 수렴 기준(절대·상대 허용오차의 결합)에서 도출하였다(§19).

풀이에 실패하면 제출본 식 (7)의 비례 제어 δ = −K_p(y − y_ref)로 대체하며, K_p = {{c:38}}의 단위는 rad/m로 해석하였다(도 단위로 읽으면
교정량이 사실상 0이 됨, §11). baseline에서 fallback이 쓰인 경우는 VI장 3절에 보고한다.

## 3. 규칙 기반 종방향 속도 제어

속도는 **FSM 상태로만** 결정한다. SAFE_STOP이 아닌 모든 상태에서 v_ref = {{c:39}}, SAFE_STOP에서 {{c:40}}이다. front_gap은 속도를
직접 바꾸지 않고, G_TRIG = {{c:18}}(회피 시작)와 G_SAFE_MIN = {{c:41}}(비상 정지)을 통해 FSM 전이로만 영향을 준다. MPC는 속도를
결정하지 않는다(이 보고서의 핵심 전제 2).

## 4. 통합 제어 구조

**표 4-1. 상태별 횡방향 제어 모드.** [데이터: 설정값 | 호스트: 해당 없음 | 버전: baseline v1.1 | 커밋: C2]

| 상태 | 라인 감지 | 라인 미감지 |
|---|---|---|
| KEEP_L2 | 라인추종 δ = −K_ey·ey_line | MPC |
| KEEP_L1 | 라인추종 | MPC |
| EVADE_L | MPC | MPC |
| RETURN_TO_L2 | MPC | MPC |
| SAFE_STOP | 직전 조향 유지 | 직전 조향 유지 |

제출본은 KEEP_L2의 라인추종과 EVADE_L·RETURN_TO_L2의 MPC만 서술한다. KEEP_L1과 라인 미검출은 KEEP_L2와 대칭으로, SAFE_STOP은
"조향 유지"로 채웠다. 라인추종 게인 K_ey = {{c:42}}의 단위는 rad/m이다(§17).

최종 조향 명령은 **변화율 제한({{c:26}}) → ±25° 절단** 순서로 후처리한 값이다. 따라서 MPC 원출력이 제약 안에 있는지와 차량에 실제로
들어간 명령이 제약 안에 있는지를 따로 기록한다. VI장에서 "원출력"은 후처리 전, "차량 입력"은 후처리 후의 값이다.
