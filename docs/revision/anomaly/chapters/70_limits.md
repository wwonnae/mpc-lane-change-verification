# VII. 한계

이 확장의 결과는 아래 조건 위에서만 성립한다. 각 항목은 결과를 실제 차량에 옮길 때 어느 방향으로 틀릴지도 함께 적었다.

1. **시뮬레이션 주입 고장이다.** 고장은 고정된 {{a:n_kinds}}종 목록에서 파라미터를 무작위로 뽑아 운동학 시뮬레이션에 주입하였다. 시나리오는 원거리·좌측
   장애물 두 가지뿐이다. 유해·무해 구분도 dev(탐지기 없음)에서 정하였다. 간헐적·복합·서서히 진행하는 고장과 실제 센서의 오차 특성은 다루지 않았다.
   실제 RC카·실차 검증은 없다.

2. **A는 참값 y를 쓰고 모델 오차가 없다 — 탐지 성능의 상한이다.** A의 ey·ir_miss 기대값은 시뮬레이터 참값 y로 계산한다. 정상 주행에서 ir_miss 불일치는
   해석적으로 0이었다(정상 {{a:thr_n_normal}}회 최대 점수 {{a:thr_irmiss_max}}). 차량 모델과 예측 모델이 같아 정상 주행의 ψ 잔차는 가정한 자이로 노이즈뿐이고,
   장애물 추적도 거의 정확하다. 따라서 A의 유해 고장 탐지 {{a:off_A_harmful}}과 그에 기댄 P1_A·P2_A의 안전 결과는 **낙관적 상한**이다. y 추정 오차·모델 불일치가
   있는 실제 시스템에서는 정상 오경보가 늘고 탐지가 늦어질 것이다(추정).

3. **정지가 즉시이다.** 차량 모델에 속도 동역학이 없어(REQ-VEH-05) 정지 판단 step에 v·dt(≤ {{a:p_vdt}}) 한 번 이동한 뒤 곧바로 v = 0이 된다. 그래서 경보가
   사고보다 한 step이라도 앞서면 대부분 "탐지 정지"로 안전하게 끝난다. 실제 차량은 제동 거리와 지연이 있으므로 표 5-2의 "충돌을 막음"은 낙관적이다.
   left_clear_stuck의 P2_A SAFE_STOP {{a:q4_n}}건은 1차선 안에서 장애물 약 0.20 m 이내까지 접근한 정지로 추정한다(dev 재현의 남은 간격 최소
   {{a:dev_lcs_gap_min}}, 평가 쪽은 정지 위치 기록 없음). 제동 거리가 있었다면 충돌했을 수 있다. 이 {{a:q4_n}}건은 P2_A가 P1_A보다 완료가 많은 이유의 일부이므로
   P2_A의 완료 우위도 일부는 이 가정에 기댄다(V장 2절).

4. **자이로 σ 가정이 틀리면 오경보가 급증한다.** σ = {{a:p_sigma_gyro}}는 데이터시트 값의 {{a:p_gyro_ratio}}로 잡은 가정이다. 실제 노이즈가 가정의 2배이면 정상
   200회 중 {{a:off_mm2_normal}}회, 5배이면 {{a:off_mm5_normal}}회가 오경보였다(IV장 표 4-4). 가정보다 조용한 쪽(0.5배)으로 틀리면 영향이 없었다. 실제 적용에는
   실측 기반 σ 보정이 필요하다.

5. **seed 안의 상관.** 같은 seed는 run 사이에 시나리오·센서 노이즈·자이로 노이즈를 공유한다. 그래서 하나의 오경보(seed {{a:corr_seed}}, step {{a:corr_step}})가
   {{a:corr_runs}}개 run에 반복되어, P2_A 불필요 정지 {{a:cl_P2_A_unn}}건 중 {{a:corr_unn_P2_A}}건을 차지하였다. {{a:cl_n}}회 기준 신뢰구간은 독립을 가정하므로 좁게
   나올 수 있다.

6. **B는 LiDAR 멈춤을 거의 잡지 못한다.** 정상 데이터로만 학습한 B1·하이브리드는 lidar_freeze를 100회 중 {{a:off_B1_lidar_freeze}}회·{{a:off_HYBRID_lidar_freeze}}회,
   B2는 {{a:off_B2_lidar_freeze}}회 탐지하였다. 정상 주행에도 front_gap이 변하지 않는 구간(무반사)이 흔해, "속도가 있는데 거리가 줄지 않는다"는 관계를
   윈도우 통계·재구성 오차가 표현하지 못하는 것으로 추정한다. A의 잔차를 특징으로 준 하이브리드도 누적(CUSUM) 없이 원시값만 받아 이 고장을 잡지 못했다.
   폐루프에서 lidar_freeze는 B 계열 정책 아래 대부분 충돌로 남았다.

7. **정상 주행 충돌 1건 — 제어기 자체의 한계.** 고장 없는 좌측 장애물 주행 seed {{a:q2_seed}}이 모든 조합에서 충돌하였다. 평가 seed가 아닌 재현 사례(seed {{a:s3173_seed}})에서
   확인한 원인은 left_clear 오판정 1회로 시작된 회피와 SAFE_STOP 쿨다운({{a:p_cooldown}})의 조합이었고, seed {{a:q2_seed}}은 같은 원인으로 추정한다(V장 5절).
   기존 보고서의 left_obstacle SAFE_STOP 100/100은 노이즈 없이 실행한 조건의 결과이다(`run_eval_v2.py:174-178`). 이 확장은 기존 보고서를 수정하지
   않으며, 노이즈가 있는 조건의 결과(V장 표 5-6)를 별도로 기록한다. 이 충돌은 탐지기가 막을 대상이 아니다. 기존 평가가 다루지 않은
   "좌측 장애물 + 센서 노이즈" 조건에서 v2 제어기가 드물게 실패한다는 사실로 기록한다.

8. **집계 정의와 기타.**
   - 완료에 SAFE_STOP을 포함하였다.
   - P2_A의 rc 대응이 만든 타임아웃 {{a:q3_n}}건은 사전 정의상 불필요 정지에 들어가지 않는다.
   - 사전 선언한 6분류 밖 결과("미정착") 1건이 있었다(사전 선언 위반, V장 Q1).
   - 성공은 복귀 후 관찰 구간({{a:p_observe}}) 기준이다. 영구 고장(ir_stuck 등)에서 그 뒤의 이탈은 보지 않았으므로 "성공"에 잠재 실패가 섞여 있을 수 있다.
   - 이탈은 차체 기하 중심 기준이라 모서리 기준보다 관대하다(II장 3절).
   - 결정성: 폐루프 dev 결과 재계산이 1회 불일치했고 원인은 미확정이다(VI장 4절). 일치 확인은 "실행 중 같은 PC에서 다른 작업 없음" 조건에서만 이루어졌다.
     오프라인 평가 결과는 다른 PC에서 재계산해 {{a:offchk_same}}개 파일이 모두 일치하였다. 폐루프 평가 결과는 같은 PC에서만 재계산하였고
     ({{a:clchk_same}}개 파일 일치), 폐루프의 다른 PC 간 재현은 dev 결과로만 확인하였다(VI장 5절).
   - 하이브리드는 B1만 확장하였다(B2 하이브리드 없음).

9. **계산 시간은 노트북 `x86` 기준이고, 임베디드 보드에서는 측정하지 않았다.** 공식 조건(H1, AC 전원 + 최고 성능)에서 정상 주행(AN)만 측정하였다(III장 5절).
   B1·하이브리드는 p99가 예산 이내였지만 최댓값이 {{a:tm_budget}}를 넘은 step이 있어, 스텝마다 예산 안에 끝난다고 보장되지 않는다. 원인은 IF 단일 샘플
   호출 비용으로 추정하며 고치지 않았다. 연산 성능이 낮은 보드에서는 이 시간이 더 길어질 것으로 추정한다. A·B2가 예산 이내였다는 결과도 이 노트북에서만
   성립한다.
