## 추정 (근거)

- **원인:** time_limit(0.045 s)이 켜진 상태에서 OS 선점 등으로 solve 하나가 45 ms 넘게 멈추면 그 solve가 시간으로 끊긴다. 그러면 x·y가 달라지고, warm start로 이후 solve가 갈라진다.
  - 근거 1: 불일치 2/2에서 첫 불일치 solve가 같은 입력, 지문 동반, run_time>45 ms였다.
  - 근거 2: 지문 없는 불일치는 0이다.
  - 근거 3: A에서는 45 ms 초과 정지가 있어도 불일치가 없었다.
  - 근거 4: 0단계 정적분석에서 벽시계에 의존하는 경로는 time_limit 하나였다.
  - 근거 5: rho 갱신 수는 모든 조건에서 일정했다(H2 배제와 부합).
- **한계:** orig 대 A의 직접 비교는 1/1000 대 0/1000이라 통계적으로 구분되지 않는다(p=1). 원인 판단은 회차 단위 기전 증거(첫 불일치 solve의 입력 동일 + 시간 절단)에 기댄다. 빈도 차이에 기댄 것이 아니다. 이 PC에서 45 ms 초과 정지는 드물다(약 1/1000 회차). run #6 러너는 훨씬 잦았을 것으로 보지만 확인되지 않았다(4단계 GitHub 러너 재현 대상).
