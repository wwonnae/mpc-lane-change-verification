# FTTI·FDTI·FRTI 근사 (시뮬레이션 기준)

> **ISO 26262·AIAG-VDA FMEA의 용어와 틀을 빌려 시뮬레이션 결과를 정리한 것이며, 표준 준수나 안전 인증이 아니다.**
> 대상은 시뮬레이션에서 주입한 고장 9종이다. 이미 있는 평가 결과 CSV만 읽었다(평가 seed 재실행 없음).
> 모든 수치는 `SAFETY_TABLES.md` T0·T5~T8에 있다. 본문에는 수치를 직접 쓰지 않는다.

## 1. 필요한 스텝이 결과 파일에 있는가 (확인됨, 파일·코드)

| 필요한 값 | 출처 | 상태 |
|---|---|---|
| 고장 시작 스텝 | 폐루프 `episodes_*.csv`의 `onset` | 있음. 기준은 1부터, runner의 `step_idx`와 같음. k ≥ onset이면 활성(`thesis_v2/anomaly/faults.py:10`, `:50`) |
| 탐지 스텝 | `episodes_P1_A.csv`·`episodes_P2_A.csv`(참고: `P1_B2/HYBRID/B1`)의 `first_alarm_step` | 있음. P0에는 탐지기가 없어 비어 있음 |
| 정지 스텝 | 같은 파일의 `finish_step`. outcome이 `탐지 정지` 또는 `SAFE_STOP`인 행 | 있음 |
| 위험 사건 스텝 | **전용 열 없음** → `outcome ∈ {충돌, 이탈}`이면 `total_steps` | 유도. 근거: `thesis_v2/anomaly/closed_loop.py:257-264`·`249-251`에서 충돌·이탈이면 그 스텝에서 break하고, `:286`에서 `total_steps=step_idx`. 위험 사건 집합은 `closed_loop.py:295` |
| 스텝 → 초 | `thesis_v2/baseline/config.py:9` `DT = 0.05`(`:79`에서 assert) | 코드 |

## 2. 정의 (근사)

- **FTTI 근사** = P0(탐지 없음)에서 (위험 사건 스텝 − 고장 시작 스텝) × dt. 고장별 분포는 T5에 있다.
  - **대표값 = 고장별 최솟값**(가장 빠른 위험 사건)이다. 이유: 안전 메커니즘은 위험 사건이 가장 빨리 오는 경우에도 제때 작동해야 하므로 시간 여유의 상한은 최악(최소)값으로 잡는 것이 보수적이다.
    p50·최댓값은 시나리오(고장 시작 시점과 장애물의 상대 위치)에 따라 FTTI가 얼마나 퍼지는지 보이려고 함께 적었다.
- **FDTI 근사** = (첫 경보 스텝 − 고장 시작 스텝) × dt. 고장 시작 전 경보는 FDTI에서 빼고 따로 센다(T6).
  - 주 대상은 탐지기 A이고, B2·HYBRID·B1은 같은 방식의 참고값이다. B1·HYBRID는 backlog 후보 14(IF 단일 샘플 시간, `repro/docs/IMPROVEMENT_BACKLOG.md:226`)와 연결된다.
  - **전제**: 탐지기는 경보 전까지 관찰만 하므로, 같은 seed의 P1_X 에피소드는 경보 전까지 P0와 같다. 이것을 "경보가 없는 P1_X 행이 P0와 같은가"로 확인했다(T0 — 표 첫머리, 불일치 seed가 있으면 거기에 나열).
- **FRTI 근사** = (정지 스텝 − 첫 경보 스텝) × dt(T7).
  - P1_A는 첫 경보 스텝에서 즉시 정지한다(v=0, 직전 조향 유지, 차량 1회 갱신 — `closed_loop.py:197-211`).
  - P2_A는 `policy_action`별로 나뉜다. `stop`은 P1과 같다. `override_lc`는 left_clear를 막힘으로 덮어써 FSM이 SAFE_STOP에 도달할 때까지 걸린다(쿨다운 포함). `override_ey`·`override_rc`는 정지하지 않는다.
- **FDTI + FRTI < FTTI** ⇔ 정지 스텝 < P0 위험 사건 스텝(같은 seed). T8에 고장별로 "N회 중 만족 M, 저하 운행 회피 G, 미달 K, 제외 J"로 적었다(M + G + K + J = N).
  - **만족**: 경보가 onset 이후이고 정지 스텝 < P0 사건 스텝.
  - **저하 운행으로 회피(정지 없음, 위험 사건 없음)**: 경보가 onset 이후이고, 정지하지 않았으며(P2의 override_ey/rc 등), 그 seed에서 해당 조합의 위험 사건이 없음.
    ISO 26262의 안전 상태에는 저하 운행이 포함될 수 있으나, 이 문서의 저하 운행은 시뮬레이션 결과로만 확인한 것이다.
  - **미달**: 경보가 없거나, 정지 스텝 ≥ P0 사건 스텝(같은 스텝도 미달 — 보수적), 또는 경보 후 정지하지 않았는데 위험 사건이 일어남(T8 미달 내역 열에서 구분).
  - **판정 제외(고장 전 오경보)**: 경보가 onset 이전이라 FDTI가 정의되지 않는다.
  - '실제로 위험 사건 아님' 열은 그 조합에서 실제 outcome이 충돌·이탈이 아니었던 수다. 조건 판정과 실제 결과를 교차 확인하는 용도다.

## 3. 계산할 수 없는 값 (데이터 없음과 이유)

- 무해 고장 3종(`ir_dropout`, `lidar_spike`, `right_clear_stuck`)의 FTTI·조건 비율은 **데이터 없음**이다. P0 위험 사건이 0회라 기준이 되는 사건 스텝이 없다(T5·T8).
- 정상 seed 5011 충돌의 FTTI·FDTI는 **데이터 없음**이다. 주입 고장이 아니라 고장 시작 스텝(`onset`)이 없다. 사건 스텝은 T9에 있다.
- MPC time_limit 고장 모드는 **데이터 없음**이다. 평가에서 발동이 0회였다(T9).
- 실제 정지 거리·제동 시간: 차량 모델에 감속 동역학이 없어(REQ-VEH-05, `repro/docs/SPEC.md:26`) 계산할 수 없다.

## 4. 한계

- **즉시 정지 가정**: SAFE_STOP과 탐지 정지는 속도를 그 스텝에 0으로 만든다(REQ-VEH-05, REQ-SPD-03). 그래서 FRTI가 이상적으로 짧게 잡힌다(P1_A의 FRTI 분포는 T7).
  실제 차량은 제동 거리만큼 더 움직이므로 조건 만족 비율(T8)은 **낙관적**이다.
  P1_A는 즉시 정지(FRTI=0 스텝)이므로, 이 조건은 사실상 '위험 사건 이전 탐지 여부'와 같다. 실제 제동 시간을 반영한 FRTI가 아니다.
- **정지 스텝의 액추에이터 고장**: 즉시 정지 스텝은 `apply_actuator`를 거치지 않아(`closed_loop.py:199-200`) steer 고장 중에도 명령한 δ_{k−1}로 갱신된다(낙관적). 저장 결과에서 결과가 바뀐 경우는 0건으로 **추정**한다(`docs/verification/mutation/RESULTS.md` 발견 사항 3, IMPROVEMENT_BACKLOG 후보 15).
- **시간 해상도**는 스텝(dt) 단위다. 같은 스텝 안의 선후는 구분하지 않는다. 그래서 FTTI·FDTI는 dt 단위 근사다.
- **위험 사건의 범위**: 완료 후 관찰 구간(`closed_loop.py:243-255`)에서는 충돌 판정으로 에피소드를 끝내지 않는다. 그 구간의 접촉은 위험 사건으로 세지 않는다.
- **가용성 손실 분리**: `right_clear_stuck`의 P2_A 타임아웃(T7·T10)은 위험 사건이 아니라 **가용성 손실**로 따로 분류한다. P0에서 이 고장은 위험 사건이 없고, 타임아웃은 P2_A의 rc 덮어쓰기가 복귀를 막아 생긴 것이다(원인은 코드와 dev 경로에 근거한 **추정**, README 상태 표).
- **독립성**: 같은 seed(5000~5099)를 run과 조합이 공유한다. 비율은 서로 독립인 시행의 비율이 아니다.
- **FTTI는 시나리오 의존**이다. 고장 시작 시점은 회피 트리거 근처에서 뽑는다(`faults.py:177-207`의 범위 샘플링). 다른 시나리오나 속도에서는 값이 달라진다.
- 이 FTTI는 ISO 26262의 "fault tolerant time interval" **정의를 시뮬레이션 사건에 대응시킨 근사**다. 해저드 분석에서 정한 값이 아니다.
