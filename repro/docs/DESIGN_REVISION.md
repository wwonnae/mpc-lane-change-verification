### 1-4. 서문에서 제출본과의 관계를 밝히는 방식 (방향)
1. 이 문서는 **2025년 12월 제출 졸업논문을 명세로 삼아 재구현·검증한 기술보고서**이며 학위 심사 제출본이 아니다. 제출본 자체는 수정하지 않고 보존한다.
2. 개정 방법: 제출본을 요구사항 명세로 삼아 제어기·시뮬레이터를 **처음부터 다시 구현**하고(기존 코드는 비교용으로만 사용), 실행 전에
   고정한 측정 기준·seed로 다시 측정했다. **이 문서의 모든 결과 수치는 재측정값**이다.
3. 재현 과정에서 확인된 사실(명세 누락, 실현 불가능한 설정값 2건, Student 입력 명세 결함, 근거 파일이 없는 수치)을 각 절에서
   "확인된 사실"로 밝히고 수정 내용을 적는다(§5 원칙).
4. 제출본이 한계로 적었던 "Student 정책의 실제 주행 검증"을 수행했고, 그 결과(논문 입력 그대로는 실패, 헤딩 추가 시 통과)를 보고한다.
5. 부록에 제출본 → 개정판 변경점 표와 측정 조건 코드표를 둔다.

- **사실·근거·영향·조치 4요소**로 씁니다: 무엇이(사실) / 어디서 확인했는지(파일·계산·실행) / 결과에 어떤 영향이 있는지 / 개정판에서
  어떻게 했는지.
- **추정은 추정으로 표시**("~로 보인다(근거: …)"), 확인되지 않은 원인은 단정하지 않습니다(예: Table 15가 어느 교사로 측정됐는지는 확인
  불가 — 그대로 "확인하지 못했다").
- 제출본 저자 = 개정판 저자이므로 1인칭 사과·변명 없이 담담히 기술.
